# История изменений

## 1.10.3 — 2026-08-26

### Создание постоянного пользователя через публичную ссылку

- Исправлена проверка Origin для форм, отправленных через DockerHub-прокси:
  настроенный публичный адрес проекта больше не сравнивается с внутренним
  адресом контейнера.
- Посторонние Origin по-прежнему отклоняются до чтения и активации приглашения.

## 1.10.2 — 2026-08-26

### Проверка пароля перед подтверждением

- На входе добавлена кнопка показа и скрытия введённого пароля.
- При создании постоянного аккаунта одна кнопка раскрывает оба поля пароля,
  чтобы пользователь мог сравнить их до отправки формы.
- Добавлена включённая по умолчанию опция сохранения через системный менеджер
  паролей браузера с безопасным fallback на стандартный autocomplete.
- Пароль остаётся скрытым по умолчанию и не сохраняется в браузерном скрипте.

## 1.10.1 — 2026-08-26

### Громкость активного трека

- Внутренний volume-transformer библиотеки заменён на собственный динамический
  PCM-gain перед Opus-кодированием, поэтому изменение применяется к уже
  играющему потоку, а не только сохраняется в состоянии очереди.
- Добавлены проверки реальных signed 16-bit PCM-сэмплов для 0%, 50%, 200%,
  clipping и изменения коэффициента без перезапуска трека.

## 1.10.0 — 2026-08-26

### Почтовые приглашения и сессии

- Добавлена закрытая slash-команда `/get-url email:`, которая выдаёт оператору
  одноразовую ссылку, привязанную к указанной почте и действующую 24 часа.
- После подтверждения email через Cloudflare One-time PIN гость получает ровно
  сутки доступа к веб-панели без passkey, лица или отпечатка пальца.
- Постоянный доступ выдаётся владельцем в панели: пользователь подтверждает
  почту, создаёт пароль и затем входит по паре email/пароль.
- Владелец `rodionaustralia@gmail.com` может отзывать аккаунты и сессии; его
  изменяющее действие ставит пятиминутный приоритет, не блокируя чтение гостям.
- Шлюз проверяет Access JWT для приглашений и передаёт приложению подписанную
  идентичность, очищая одноимённые заголовки, присланные клиентом.

### Безопасный выпуск

- Добавлена отдельная staging-сборка без Discord-подключения и музыки, с
  отдельной SQLite-базой и локальным портом 8788.
- Добавлены тесты одноразовых приглашений, постоянных аккаунтов, приоритета
  владельца, подписи шлюза и команды Discord.

## 1.9.0 — 2026-08-23

### Локальные медиафайлы

- `/play` теперь принимает Discord-вложение `file` вместо текстового `query` и
  воспроизводит аудиодорожку любого аудио- или видеоконтейнера, поддерживаемого FFmpeg.
- Вложения потоково загружаются только с Discord CDN, ограничиваются настройкой
  `MUSIC_FILE_MAX_BYTES`, проверяются через `ffprobe` и сохраняются в аудиокэше.
- Файловые треки сохраняются в очередях и плейлистах по безопасному имени кэша,
  поэтому продолжают работать после перезапуска без зависимости от CDN-ссылки.

### Авторизация с телефона

- Добавлена slash-команда `/phone`, которая выдаёт короткоживущую одноразовую
  ссылку подключения в приватном ephemeral-ответе.
- Команда проверяет наличие роли `Ботовод`; администраторы и остальные участники
  без этой роли не могут создать pairing-ссылку.

## 1.8.3 — 2026-08-20

### Громкость и воспроизведение

- Громкость стала сервер-авторитетной: REST API возвращает фактически применённый
  уровень, а панель подтверждает изменение только после ответа процесса бота.
- Ползунок отправляет изменения на хост с коротким debounce и последовательной
  очередью запросов, поэтому быстрые движения больше не применяются в обратном
  порядке и не создают лишнюю нагрузку.
- Исправлено восстановление громкости `0%` после перезапуска; нечисловые значения
  больше не могут попасть в inline-volume преобразователь Discord AudioPlayer.
- Добавлена настройка `MUSIC_DEFAULT_VOLUME_PERCENT=0..200` в `.env` для новых
  серверных очередей; значение ограничивается и применяется к активному PCM-потоку.
- Добавлены регрессионные тесты применения громкости к host-side audio resource.

### Демонстрация UI

- GitHub Pages публикует настоящий интерфейс из `src/web/public`, а не отдельный
  макет. На публичном домене Discord API заменяется локальным безопасным демо-слоем.
- Демо сохраняет реальные desktop/mobile-компоненты и интерактивность, используя
  только синтетические серверы, участников, историю, музыку и плейлисты.

## 1.8.1 — 2026-08-20

### Docker и режимы развёртывания

- Добавлено переключение между локальным компьютером и постоянным сервером через
  `DEPLOYMENT_MODE`, `REMOTE_ACCESS_PROVIDER` и `COMPOSE_PROFILES` в `.env`.
- Локальный режим продолжает использовать ngrok по запросу, а серверный запускает
  закреплённый контейнер Cloudflare Tunnel без публикации панели в интернет.
- Публичный HTTPS-адрес серверной панели задаётся через `PUBLIC_BASE_URL`; QR-коды
  подключения телефона формируются для постоянного домена Cloudflare.
- Лимиты памяти и CPU для бота, PO Token Provider и Cloudflare Tunnel вынесены в
  `.env`, чтобы загрузка музыки не вытесняла стриминг и системные процессы.
- Health-check учитывает настраиваемый `WEB_PORT`; подключённые каталоги `config`,
  `data` и `logs` продолжают сохраняться между пересозданиями контейнера.
- Добавлена ранняя проверка несовместимых режимов и небезопасного публичного URL,
  а веб-панель показывает инструкции для выбранного провайдера доступа.

## 1.8.0 — 2026-08-20

### Безопасность и доступ

- Добавлена RBAC на уровне API: мутабельные маршруты по умолчанию требуют роль
  админа, а проверки для build/wipe/rebuild, модерации и действий с голосом
  выполняются централизованно в веб-слое.
- Для всех мутабельных API включены CSRF-потверждения и защита от гонок в сессии
  панели: отдельные токены для запросов и обязательная выдача в ответах/заголовках.
- Усилены сессии: для мобильных устройств введена ротация cookie-сессий,
  отзыв при смене IP/UA и по неактивности; добавлена проверка подозрительных
  отклонений во избежание перехвата.
- Для pairing-кода добавлен лимит неуспешных попыток и отдельное окно блокировки,
  чтобы закрыть «перебор» токенов подтверждения.

### Сервисная стабильность и аудит

- Добавлены ограничения скорости для mutating-эндпоинтов, rate-limit для мутаций
  и централизованные статусы ошибок в API.
- Реализован аудит деструктивных действий (build/wipe/rebuild, модерация,
  голосовые операции, управление музыкой) и единый журнал с привязкой к сессии,
  IP и user-agent.
- Расширены политики очистки: сообщения логируются в историю с архивированием
  по TTL и безопасной батчевой ротацией, очередь/сессии/история теперь хранятся
  в SQLite как единый источник состояния.

### Веб-панель и мобильный режим

- Добавлены новые мобильные сценарии: QR/сессии отображаются со списком подключённых
  устройств, добавлена явная кнопка сброса конкретной/всех мобильных сессий,
  подтверждение повторного сканирования/обновления сессии.
- Уменьшена зависимость от `x-forwarded-*` для локального режима; удалённые подключения
  опираются на локальную детекцию и защищённый tunnel flow.
- Для мобильного UX добавлены адаптивная навигация/панели, скролл-ограничения,
  сворачивание и упрощённый доступ к разделам на экран 390×844.

### Плейлисты, кэш и медиа-поток

- Введены лимиты и авто-чистка аудиокэша: макс. число файлов, размер и возраст
  файлов с батчевой очисткой в фоне; скачивание выполняется с кооперативным
  dedupe и безопасным повторным использованием загрузок.
- Локальная библиотека плейлистов стала более управляемой: каждый плейлист имеет
  ID и имя, сохранение идёт с отдельным снапшотом треков и времени, а повторный
  запуск продолжает позицию предыдущего слушания.
- Добавлены улучшенные статусы треков в UI (добавлено/скачивается/кэшировано/ошибка),
  кнопки «play now» и «remove» для каждого пункта очереди и отображение прогресса
  по времени + телеметрии стабильности в веб-панели.

### Docker и runtime

- Добавлены runtime-оптимизации для окружения контейнера:
  отдельный pinned image-tag для бота и фиксированные версии сервисов, расширенные
  переменные контроля лимитов кэша и истории, автоматический health-check и более
  явный lifecycle для сессий.

## 1.5.0 — 2026-08-20

### Новые возможности

- Возле каждого ожидающего трека в веб-панели добавлены кнопки немедленного
  включения и удаления из очереди. Для действий используются стабильные
  идентификаторы треков, поэтому обновление списка не затрагивает соседние песни.
- Добавлено локальное сохранение текущего трека и всей очереди в фоне без
  остановки воспроизведения. Состояние каждой загрузки записывается в атомарный
  JSON-манифест в `data/playlists/<guild-id>/`.
- Перед сохранением можно выбрать уже существующее имя плейлиста или ввести
  новое. Повторное имя создаёт новую версию, сохраняя предыдущие манифесты.
- Добавлена отдельная сворачиваемая панель «Плейлисты»: библиотека показывает
  уникальные имена, количество версий, прогресс и статус, а треки последней
  версии лениво подгружаются только при раскрытии.
- Незавершённые фоновые сохранения автоматически возобновляются после
  перезапуска контейнера. Одновременно во всём боте выполняются не более двух
  загрузок.
- Очередь теперь сохраняет текущий трек, громкость, текстовый и голосовой каналы
  и восстанавливается после рестарта. Если голосовой канал доступен, бот
  автоматически подключается и продолжает очередь с начала прерванного трека.
- Выбранный сервер и раскладка панелей сохраняются в браузере; сетевые запросы
  панели получили таймауты и устойчивую параллельную загрузку независимых
  разделов.

### Исправления стабильности

- Устранены гонки между `skip`, событиями `Idle`, ошибками аудиоплеера и поздним
  завершением FFmpeg. Устаревшие и повторные события больше не могут дважды
  сдвинуть очередь или запустить лишний трек.
- Параллельное воспроизведение и сохранение одной ссылки теперь используют одну
  общую загрузку `yt-dlp`, исключая дублирование файлов и процессов.
- Фоновые задачи защищены от необработанных исключений, повреждённых манифестов
  и рестарта во время загрузки; промежуточные записи переводятся обратно в
  ожидающие и безопасно продолжаются.
- Запись состояния очереди и конфигурации сделана атомарной. Исправлена очистка
  состояния в ESM и добавлена проверка повреждённых или неверно типизированных
  конфигов.
- Операции Build/Wipe структуры сериализуются отдельно для каждого сервера;
  rebuild выполняет очистку и создание под одной блокировкой.
- SQLite переведён в режим WAL, включены `synchronous=NORMAL` и
  `busy_timeout=5000` для устойчивости при конкурентных чтениях и записи.
- Discord lifecycle обрабатывает disconnect/reconnecting/resume/error и
  invalidated-сессию; завершение по сигналу сохраняет очередь перед выходом.

### Веб-панель, API и зависимости

- `/health` отражает реальную готовность Discord-клиента и возвращает `503`,
  пока бот не вошёл в сеть.
- JSON-запросы ограничены 1 МБ; некорректные тела, неизвестные треки и ID
  плейлистов возвращают корректные `400`, `404` и `413` без шумных stack trace.
- Добавлены API получения сгруппированной библиотеки и ленивой загрузки деталей
  отдельного сохранённого плейлиста.
- Обновлён транзитивный пакет `tar` до безопасной версии `7.5.22`; `bun audit`
  не обнаруживает известных уязвимостей.
- Улучшены подписи, статусы, адаптивное расположение элементов и доступные
  `aria-label` для управления очередью и сохранёнными плейлистами.

## 1.3.0 — 2026-08-20

### Новые возможности

- Добавлено воспроизведение YouTube-плейлистов: бот разбирает ссылку на отдельные
  треки, получает их названия и добавляет в очередь в исходном порядке.
- Добавлена поддержка динамических YouTube Mix (`list=RD...`) с сохранением
  стартового видео и ограничением очереди до 500 доступных треков.
- Добавлена опциональная интеграция PO Token Provider для более стабильной
  загрузки YouTube-аудио через `yt-dlp`.
- В веб-панели появился живой прогресс воспроизведения: уже проигранное и общее
  время, оставшееся время и полоса прогресса.
- В веб-панели появились показатели стабильности потока: буфер, состояние
  проигрывателя и голосового соединения, скорость декодирования и последняя
  обнаруженная проблема.

### Улучшения и исправления

- Устранена самопроизвольная остановка музыки из-за накопления данных FFmpeg:
  поток теперь корректно соблюдает обратное давление.
- Добавлено атомарное массовое добавление плейлистов с проверкой максимального
  размера очереди и сохранением порядка треков.
- Состояние музыки в веб-панели обновляется каждую секунду без лишней полной
  перерисовки очереди.
- Добавлен health-check Docker-контейнера и обновлена Compose-конфигурация для
  запуска опционального PO Token Provider.
- Исправлено название стандартной роли `Новичок`.
